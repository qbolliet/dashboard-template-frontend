# Chart

`<Chart>` trace une variable `y` en fonction de `x`, avec une troisième dimension `z` et des
canaux de série `hue` facultatifs. Vous ne choisissez pas le type de graphique : il se déduit
du type des colonnes branchées. Il ne fait aucune requête — il reçoit des lignes (ou des
valeurs déjà agrégées) et les métadonnées de leurs colonnes, ce qui permet de l'installer
seul depuis le registry.

## Explorer les paramètres

Le playground pilote une instance de `<Chart>` : chaque contrôle modifie le rendu **et**
le code affiché à côté. Les props laissées à leur valeur par défaut n'apparaissent pas
dans le code — seul ce que vous avez changé s'y trouve, imports et jeu de données compris.

## Choix automatique du tracé

Chaque colonne est d'un des trois types **date**, **nombre** ou **catégorie**, et la
combinaison de `x`, `y` et `z` décide du tracé :

| `x` | `y` | `z` | Tracé |
|---|---|---|---|
| date ou nombre | nombre | — | ligne (`fill="none"` : nuage de points) |
| catégorie | nombre ou date | — | barres verticales |
| date ou nombre | catégorie | — | barres horizontales |
| catégorie | catégorie | nombre | heatmap |
| catégorie | nombre ou date | nombre | violon vertical |
| nombre ou date | catégorie | nombre | violon horizontal |
| nombre ou date | nombre ou date | nombre | densité |
| (toute combinaison) | | nombre, `zMark="bubble"` | bulles |

`z` doit être numérique, sinon `<Chart>` lève. Les propriétés `categorical-x` et
`categorical-y` forcent le traitement d'un axe en catégorie — utile pour un entier qui est un
code (une année vue comme une étiquette, un numéro de département).

## Troisième dimension : densité ou bulles

Par défaut (`zMark="density"`), `z` se lit en **couleur ou en densité** : heatmap, violon ou
densité 2-D selon les types de `x` et `y`. Avec `zMark="bubble"`, il se lit en **taille** :
chaque observation devient un marqueur centré en (x, y) dont l'**aire** est proportionnelle à
`z` — doubler `z` double l'aire, pas le rayon. Un `z` nul, négatif ou absent n'est pas dessiné
(une aire négative n'a pas de sens) ; si aucun `z` n'est positif, un message remplace le tracé.

```jsx
// Deux catégories : une bulle par cellule (et par série), comme une case de heatmap
<Chart data={rows} x="Mois" y="Pays" z="Inflation" zMark="bubble" />

// Une catégorie, un nombre : une bulle par ligne, séries décalées dans la bande
<Chart data={rows} x="Modèle" y="RMSE" z="Échantillon" zMark="bubble" hue="Jeu" />

// Deux nombres : un nuage de bulles, survol au plus proche (voronoï)
<Chart data={rows} x="ChômageTaux" y="EmploiTaux" z="Densité" zMark="bubble" hue="Type" />
```

- **Position** : centre de la bande sur un axe catégoriel — du slot de la série quand le
  canal couleur est actif —, valeur exacte sur un axe continu.
- **Taille** : la plus grande bulle a le rayon du token `--chart-bubble-max-radius`
  (`marks/_tokens.scss`), plafonné à la demi-bande (demi-slot) d'un axe catégoriel. Les
  plus grandes sont dessinées d'abord ; leur remplissage est translucide
  (`--chart-marks-bubble-fill-opacity`).
- **Canaux** : la couleur remplit (`fill="fill"`) ou trace le contour (`fill="line"`) ; le
  style hachure ou pointille ; le marqueur change la forme à aire égale. `fill="none"`
  retombe sur `"fill"`, comme pour les autres tracés à `z`.
- **Zoom, brush, mini-vues** : ceux du tracé remplacé (heatmap, violon ou densité). Zoomer
  déplace les bulles sans les redimensionner.
- **Légende** : trois cercles de référence, au format de `z`, titrés par `labels.z`.
- **Agrégation** : sur deux catégories, `useAggregatedChart({ …, zMark: 'bubble' })` fait
  regrouper l'API par x, y et les colonnes `hue` (une bulle par cellule et par série) ; sur
  des lignes brutes, `<Chart>` réduit chaque cellule avec l'agrégation par défaut de `z`.
  Ailleurs, chaque ligne est une bulle. Avec `aggregate`, `z` est lu tel quel.

Une bulle proche du bord d'un axe continu peut être rognée par le cadre, comme un point du
nuage. `zMark` ne vaut que pour un jeu unique : une liste de jeux ignore `z`.

## Typer et formater avec les métadonnées : `fields`

Sans autre indication, `<Chart>` devine le type d'une colonne en échantillonnant ses valeurs,
et une chaîne comme `'01012100'` ou `'2024'` peut être prise pour un nombre ou une date. Avec
la prop `fields` — les métadonnées de colonnes renvoyées par l'API, avec les lignes —, le
type de chaque colonne décrite vient de sa **famille de type** :

| `typeFamily` | Type de colonne |
|---|---|
| `DATE`, `TIMESTAMP` | date |
| `INTEGER`, `NUMBER`, non catégoriel | nombre |
| tout le reste (`TEXT`, `BOOLEAN`, `OTHER`, ou une colonne `isCategorical`) | catégorie |

La détection sur les valeurs n'est alors même pas appelée pour cette colonne. `fields` règle
aussi la mise en forme : le `displayFormat` (un format d3 : `,.1f`, `.1%`) et l'`unit` d'une
colonne numérique mettent en forme son axe et son infobulle. Une prop `format={{ y: '.1f' }}`
explicite l'emporte toujours sur ce qui est déduit.

```jsx
const { rows, fields } = useFactTable();

<Chart data={rows} fields={fields} x="date_obs" y="gdp" hue="country" />
```

Une colonne que `fields` ne décrit pas retombe sur la détection par échantillon, comme avant.

## Agréger côté serveur

Un tracé qui **regroupe** — barres, barres horizontales, heatmap, ligne agrégée — réduit
plusieurs lignes à une valeur par groupe. Fait sur les lignes chargées, ce calcul ne voit
qu'une page de données (100 lignes) et ne sait rien de l'agrégation voulue de la mesure : la
moyenne d'un taux n'est pas sa somme. Il y a donc deux façons de le faire, selon d'où viennent
les lignes.

**Lignes brutes en mémoire.** Le graphique réduit lui-même ses lignes avec la
`defaultAggregation` de la mesure (`SUM`, `AVG`…) déclarée dans `fields`, et la moyenne quand
elle n'en déclare pas.

**Valeurs agrégées par l'API.** `useAggregatedChart` interroge `getAggregates` sur **tout** le
jeu filtré et rend les props de `<Chart>`, dont `aggregate`. Cette prop dit au graphique que
`data` contient déjà une ligne par groupe — la valeur dans `y` (`x` pour des barres
horizontales, `z` pour une heatmap) — et qu'il ne doit ni la regrouper ni la recalculer. Pour
`aggregate`, l'agrégation de la mesure ne sert qu'à décider comment les minimaps d'une heatmap
projettent les cellules (sommées pour `SUM` / `COUNT`, moyennées sinon). Un tableau de mesures
trace plusieurs mesures en format long, avec `hue` = mesure.

```jsx
const chart = useAggregatedChart({
  x: 'country', measures: ['gdp'], fields, structuredFilters,
});

<Chart {...chart.chartProps} />
```

Le hook choisit lui-même le mode d'après les métadonnées : serveur pour les tracés qui
regroupent, lignes brutes pour le nuage de points, le violon et la densité, dont le tracé a
besoin des observations individuelles. Ces lignes brutes, il les charge lui-même — les seules
colonnes tracées, sous `structuredFilters`, jusqu'à 1000 lignes — sauf si vous lui passez
`rows`. Tant que `fields` ne décrit pas toutes les colonnes tracées, il retombe sur les lignes
brutes — on ne sait pas typer sans elles. Une colonne de groupe qui porte un code (nc8, INSEE)
s'affiche par son libellé, lu dans la colonne `<nom>__label` que renvoie `getAggregates`.

## Données attendues

`data` est un tableau d'objets au **format long**, une ligne par observation, dont les clés
sont les noms de colonnes — exactement ce que renvoie `getFactTableWithMetadata` avec
`format: OBJECTS`. Les dates peuvent arriver en chaînes ISO 8601 : le graphique les convertit.

| Prop | Rôle |
|---|---|
| `x`, `y` | colonnes de l'abscisse et de l'ordonnée (`y` est obligatoire) |
| `z` | troisième dimension : heatmap, violon, densité — ou bulles avec `zMark="bubble"` |
| `zMark` | `'density'` (défaut) ou `'bubble'` : marque de la troisième dimension |
| `hue` | colonne(s) de série : couleur, puis style de trait, puis marqueur |
| `fields` | métadonnées de colonnes : types, `displayFormat`, `unit`, agrégation par défaut |
| `aggregate` | `data` est déjà agrégé par l'API : ne pas ré-agréger |
| `format`, `labels` | formats d3 et intitulés d'axes, qui l'emportent sur ce qui est déduit |

La table complète des props est générée depuis le code ; les formats d3 passent par la locale
du site (`locale`), jamais par un format américain écrit en dur.
