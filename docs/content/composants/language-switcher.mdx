# LanguageSwitcher

`<LanguageSwitcher>` est un bouton drapeau qui ouvre un menu déroulant des langues,
selon le motif ARIA *Collapsible Dropdown Listbox* : les flèches parcourent la liste,
`Début` et `Fin` sautent aux extrémités, `Échap` referme le menu en rendant le focus au
bouton. Il ignore tout de l'internationalisation du site — ni `src/i18n/`, ni le
routage, ni `LocaleProvider` — et reçoit ses langues, sa valeur et ses libellés en
props. C'est cette ignorance qui le rend installable seul depuis le registry, dans un
projet qui n'a ni manifeste ni dictionnaire.

Le header du template ne monte pas `<LanguageSwitcher>` directement, mais
`<LocaleSwitcher>` : un adaptateur sans rendu propre qui traduit `site.locales`, le
dictionnaire courant et une navigation qui préserve le chemin en props pour la
présentation. Cette frontière — la présentation d'un côté, le branchement de l'autre —
est ce qui permet de faire évoluer le routage sans toucher au composant, et de
réutiliser le composant sans le routage.

## Ajouter ou retirer une langue

En autonome, la liste est une prop : passez `languages` avec les langues voulues,
chacune un `{ code, country, name }` — c'est ce que montre l'exemple *Liste
personnalisée* ci-dessus.

Branché sur le site via `<LocaleSwitcher>`, la liste vient de la configuration :
ajoutez le code dans `site.locales` et son pays dans `site.localeCountries`
(`config/site.config.json`), puis complétez le dictionnaire de la nouvelle langue sous
`src/i18n/dictionaries/`. `npm run check:i18n` liste ce qu'il reste à faire — la
procédure complète est dans [Internationalisation](/guides/internationalisation).

## Drapeaux

Chaque drapeau passe par une fonction `flagSrc`, qui résout un code pays en URL
d'image ; le défaut interroge flagcdn.com, un CDN public de drapeaux SVG. Fournir une
autre fonction — pointant vers des fichiers `public/flags/<iso2>.svg` par exemple —
bascule sur des drapeaux auto-hébergés sans toucher au composant, comme le montre
l'exemple *Drapeaux auto-hébergés* ci-dessus. Les huit drapeaux des langues par défaut
(`public/flags/{de,es,fr,gb,it,jp,nl,pt}.svg`) sont livrés avec cet exemple et
s'installent avec lui depuis le registry ; pour une langue de plus, déposez son
`<iso2>.svg` au même endroit.

Le code pays est toujours rendu en texte, sous l'image, dans la même cellule de grille :
la pastille garde donc exactement la même boîte que le drapeau soit chargé, en attente
ou en échec. Le repli n'est pourtant pas du CSS pur : un `<img alt="">` qui échoue n'est
**pas** invisible — dès que le CSS lui impose une taille, Chromium y peint l'icône
d'image cassée, par-dessus le texte. `<FlagChip>` garde donc un état local minimal :
l'image reste cachée jusqu'à son `onLoad`, et elle est retirée du DOM sur `onError`
(ou n'est jamais rendue si `flagSrc` renvoie `null`). Tant que le drapeau n'est pas
arrivé, ou s'il n'arrive jamais, c'est le code pays qui s'affiche.
